# Native Home Assistant integration

The native integration is the simplest way to use EspControl Immich Companion. It creates one Home Assistant device for each config entry and does not require MQTT, a broker, or a separate app container.

Copy `custom_components/immich_frames` into the Home Assistant configuration directory as `custom_components/immich_frames`, restart Home Assistant, then choose **Settings → Devices & services → Add integration → EspControl Immich Companion**.

Setup is progressive. First enter the Immich URL and read-only API key; Home Assistant verifies the server before continuing. Next choose **All photos**, **Albums**, **Memories**, or **Keywords**. Albums mode loads a searchable list of albums available to the connected account, including shared albums, and lets you select one or more by name. Photos from any selected album are included together. The API key needs `album.read` permission in addition to the photo permissions. If the list is empty or cannot be loaded, setup explains the problem and lets you retry or choose another source. Existing frames retain their saved album IDs without any migration. Next, **Set up the frame** asks for the frame name, output size and display mode. **Configure photo display** then asks for Photo fit, photo orientation filter and slideshow interval. Pair portrait photos has one extra **Configure portrait pairs** step for the date window and option to only show portraits in pairs; single-image mode skips it. Add one integration entry for each frame. The integration polls Immich, renders the selected image or pair locally, and keeps the last complete image in Home Assistant's `.storage` directory for temporary upstream outages.

The created device includes the rendered image, photo metadata sensors, slideshow pause/resume, next/previous/refresh/clear-cache buttons, a “Show photo details for” control that chooses the single image or the left/right photo in a pair for the detail sensors, and the interval control.

When adding another frame, setup offers existing Immich connections by server URL and frame name. Select one to reuse its URL and API key, or choose **Connect to another Immich server** to enter different details. Saved connections are verified again before continuing. Each frame has its own source and display settings, and keeps a copy of the connection details so deleting the original frame does not disconnect the others. Updating a key in one frame does not update other existing frames.

For HACS, add this repository as a custom repository of type **Integration**, then install EspControl Immich Companion and restart Home Assistant. Manual copying is also supported for development branches.

To change your mind during setup, use **Next action** on the album, memories, Keywords, frame setup, photo display or pairing screen. Select a **Back** option (or **Change photo source** on the frame setup screen), then use the button below. The form retains your earlier selections and display settings. Choose **Save frame** on the final photo display or portrait pairing screen to finish. Earlier steps show **Continue**. Going back through these steps retains your choices, including pairing settings if you switch modes. Only filters for the selected source are saved.

After setup, open **Settings → Devices & services → EspControl Immich Companion** and choose **Configure** for the frame you want to edit. Choose **Change photo source** to switch between All photos, Albums, Memories and Keywords. A shortcut opens the current source’s album selection, search text or memory settings directly. Choose **Change photo display settings** to edit single images or portrait pairs, the orientation filter, pairing rules, slideshow interval or frame name. Your saved settings are filled in, and the saved server URL and API key are reused. Continue through the short frame and photo display steps, plus pairing settings when Pair portrait photos is selected. On the final step, select **Save frame** under **Next action**, then press **Submit** to apply the changes. The frame reloads automatically and retains its existing device and entity IDs. Closing the form without saving leaves the frame unchanged. The frame entry’s **Reconfigure** menu also remains available.

Choose **Screen shape** on the display settings screen to match the target screen: **Landscape (16:10, 1280 × 800)**, **Portrait (10:16, 800 × 1280)**, or **Square (1:1, 720 × 720)**. Output always has the selected dimensions. This controls the screen shape independently of the **Photo orientation filter**, which controls which photos can be selected.

On **Configure photo display**, under **Photo fit**, choose **Crop to fit** to fill the frame by trimming photo edges, or **Show full image** to keep the whole photo with a dim colour sampled from it filling any empty space. Photos retain their proportions in both modes. The choice applies to single photos, both photos in a pair, and the single-photo fallback when no companion is available. Pairs stay side by side with a 1-pixel black divider; each photo uses its own background colour. Dark areas within photos stay untouched.

Change this through **Configure → Change photo display settings**. This replaces the old **Keep original aspect ratio for single photos** checkbox. Existing single-photo frames and frames with that checkbox enabled default to **Show full image**; other existing pair frames default to **Crop to fit**. New single-photo frames default to **Show full image**; new pair frames default to **Crop to fit**. Old cached images and images from a different fit or screen shape are discarded, so Immich must be reachable to generate the first image with the new settings.

The **Photo date** sensor displays dates as **14 May, 2007** (day, full month name, year). It uses the date recorded with the photo, without changing it to Home Assistant’s timezone. The full timestamp remains in the internal photo metadata for pairing and caching. Missing or invalid dates appear as unknown.

The background colour calculation follows [ESPFrame’s former accent-fill helper](https://github.com/jtenniswood/espframe/blob/47ae12c7b29d73f7623c9cc13a7bac7435c10ae8/components/espframe/espframe_helpers.h#L335-L387), using RGB preview pixels. ESPFrame later removed its border-detection implementation; this integration creates the padding separately and never identifies borders by looking for black pixels. Cached images are reused only when their fit setting and output dimensions match.

Photo selection defaults to **Mixed (landscapes and portraits)**, which also includes square photos. Use **Photo orientation filter** to choose **Landscape photos only** or **Portrait photos only** (or square photos only). **Pair portrait photos** pairs compatible portraits without removing landscapes from the slideshow. Enable **Only show portraits in pairs** to skip portraits that have no companion within the date window; landscapes and square photos still appear individually. Leave it off to allow unmatched portraits as single images. To show exclusively portrait pairs, combine **Portrait photos only**, **Pair portrait photos**, and **Only show portraits in pairs**. Existing orientation selections are preserved.
