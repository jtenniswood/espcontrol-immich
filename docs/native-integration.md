# Native Home Assistant integration

The native integration is the simplest way to use EspControl Immich Companion. It creates one Home Assistant device for each config entry and does not require MQTT, a broker, or a separate app container.

Copy `custom_components/immich_frames` into the Home Assistant configuration directory as `custom_components/immich_frames`, restart Home Assistant, then choose **Settings → Devices & services → Add integration → EspControl Immich Companion**.

Setup is progressive. First enter the Immich URL and read-only API key; Home Assistant verifies the server before continuing. Next choose **All photos**, **Albums**, **Memories**, or **Keywords**. Albums mode loads a searchable list of albums available to the connected account, including shared albums, and lets you select one or more by name. Photos from any selected album are included together. The API key needs `album.read` permission in addition to the photo permissions. If the list is empty or cannot be loaded, setup explains the problem and lets you retry or choose another source. Existing frames retain their saved album IDs without any migration. Finally, **Set up the frame** asks only for the frame name. Use the button below to finish. New frames start with the 1280 × 800 landscape target, single images, **Show full image**, mixed photo orientations and a 30-second interval. Choose the matching **Screen shape** and photo/pairing preferences afterwards on the device page; setup no longer asks for them. Memories uses a two-day window and no fallback initially; change these afterwards through **Configure → Change memory settings**. Add one integration entry for each frame. The integration polls Immich, renders the selected image or pair locally, and keeps the last complete image in Home Assistant's `.storage` directory for temporary upstream outages.

The created device includes the rendered image, photo metadata sensors, slideshow pause/resume, next/previous/refresh/clear-cache buttons, and the interval control. Photo detail sensors always describe the single photo, or the left photo in a pair.

When adding another frame, setup offers existing Immich connections by server URL and frame name. Select one to reuse its URL and API key, or choose **Connect to another Immich server** to enter different details. Saved connections are verified again before continuing. Each frame has its own source and display settings, and keeps a copy of the connection details so deleting the original frame does not disconnect the others. Updating a key in one frame does not update other existing frames.

For HACS, add this repository as a custom repository of type **Integration**, then install EspControl Immich Companion and restart Home Assistant. Manual copying is also supported for development branches.

During setup, use the button at the bottom of each form to continue. The frame name is the final step and saves the frame. Only filters for the selected source are saved. You can change the frame’s settings after setup using **Configure**.

On the frame’s device page, **Configuration** contains **Screen shape**, **Photo fit**, **Display mode**, **Photo orientation**, and **Pairing window** (0–7 days, default 2 days). Zero days pairs portraits taken on the same date. Pairing settings apply when **Display mode** is **Pair portrait photos**; they remain saved when showing single images. **Slide interval** also appears in **Configuration**. Slideshow pause/resume and navigation remain in **Controls**.

Device settings save immediately and reload the frame to apply the new photo rules. A reload restarts the slideshow and clears previous-slide history. Immich must be reachable for the first image after a change: cached images from different modes, orientations, pairing rules, photo fits or output dimensions are rejected. Existing settings are preserved; caches from older versions that cannot confirm non-default pairing/orientation rules are regenerated. The slide interval control updates the timer without a reload.

After setup, open **Settings → Devices & services → EspControl Immich Companion** and choose **Configure** for the frame you want to edit. Choose **Change photo source** to switch between All photos, Albums, Memories and Keywords. A shortcut opens the current source’s album selection, search text or memory settings directly. Choose **Change photo display settings** to edit single images or portrait pairs, the orientation filter, pairing rules, slideshow interval or frame name. Your saved settings are filled in, and the saved server URL and API key are reused. Continue through the short frame and photo display steps, plus pairing settings when Pair portrait photos is selected. On the final step, select **Save frame** under **Next action**, then press **Submit** to apply the changes. The frame reloads automatically and retains its existing device and entity IDs. Closing the form without saving leaves the frame unchanged. The frame entry’s **Reconfigure** menu also remains available.

After setup, open the frame’s device page and use **Configuration → Screen shape** to choose Landscape, Portrait or Square. The same **Screen shape** choice is also available through **Configure → Change photo display settings**.

| Screen shape | Output resolution |
|---|---|
| Landscape | 1280 × 800 |
| Portrait | 800 × 1280 |
| Square | 720 × 720 |

Landscape is the default. Existing landscape, portrait and square settings retain their dimensions. Saved device presets automatically migrate to their corresponding shape: JC1060P470 to Landscape, JC4880P443 to Portrait, and 4848S040 to Square. Their next image uses the dimensions above.

The choice is saved automatically and reloads the frame to generate a new image. Immich must be reachable for the first image at the new resolution; cached images and previous-slide history at the old resolution are not reused. Reloading starts the slideshow again. Output always has the selected dimensions. This controls output resolution independently of the **Photo orientation filter**, which controls which photos can be selected.

On the device page, under **Configuration → Photo fit**, choose **Crop to fit** to fill the frame by trimming photo edges, or **Show full image** to keep the whole photo with a dim colour sampled from it filling any empty space. Photos retain their proportions in both modes. The choice applies to single photos, both photos in a pair, and the single-photo fallback when no companion is available. Pairs stay side by side with a 1-pixel black divider; each photo uses its own background colour. Dark areas within photos stay untouched.

The same setting is also available through **Configure → Change photo display settings**. This replaces the old **Keep original aspect ratio for single photos** checkbox. Existing single-photo frames and frames with that checkbox enabled default to **Show full image**; other existing pair frames default to **Crop to fit**. New frames default to **Show full image**. Changing display mode on the device page preserves the current photo fit, including on older installations. Old cached images and images from a different fit or screen shape are discarded, so Immich must be reachable to generate the first image with the new settings.

The **Date** sensor displays dates as **14 May, 2007** (day, full month name, year). It uses the date recorded with the photo, without changing it to Home Assistant’s timezone. The full timestamp remains in the internal photo metadata for pairing and caching. Missing or invalid dates appear blank. All detail sensors leave missing values blank; a rating of zero still appears as 0.

The background colour calculation follows [ESPFrame’s former accent-fill helper](https://github.com/jtenniswood/espframe/blob/47ae12c7b29d73f7623c9cc13a7bac7435c10ae8/components/espframe/espframe_helpers.h#L335-L387), using RGB preview pixels. ESPFrame later removed its border-detection implementation; this integration creates the padding separately and never identifies borders by looking for black pixels. Cached images are reused only when their photo rules, fit setting and output dimensions match.

Photo selection defaults to **Mixed (landscapes and portraits)**, which also includes square photos. Use **Configuration → Photo orientation** on the device page to choose **Landscape photos only** or **Portrait photos only** (or square photos only). **Pair portrait photos** pairs compatible portraits without removing landscapes from the slideshow. Portraits without a companion within the date window appear individually, as do landscapes and square photos. Combine **Portrait photos only** and **Pair portrait photos** to limit the slideshow to portraits, paired when a companion is available. Existing orientation selections are preserved.
